<objective>
## Goal
Fix Vercel deployment dengan split routing: hanya `/api/*` ke serverless function, static files via Vercel CDN — menyelesaikan masalah alternating antara API 404 dan DB connection overwhelm.

## Purpose
Sejak Phase 09, deployment production tidak stabil. Dua masalah saling bertentangan:
1. Saat single catch-all route (`routes`) → semua static asset requests masuk ke function → concurrent DB init → NeonDB overwhelmed
2. Saat split routing dengan `outputDirectory:dist` → `express.static(distPath)` di function crash karena `dist/` tidak accessible dari dalam serverless function

Keduanya harus diperbaiki sekaligus: split routing yang benar + hapus dead code static serving dari function.

## Output
- `vercel.json`: split routing dengan `outputDirectory: dist`
- `api-handler.ts`: hapus static file serving, function murni API-only
</objective>

<task type="auto">
  <name>Task 1: Fix vercel.json — split routing dengan outputDirectory</name>
  <files>vercel.json</files>
  <action>
    Ganti seluruh isi vercel.json dengan:

    ```json
    {
      "version": 2,
      "buildCommand": "npm run build",
      "outputDirectory": "dist",
      "functions": {
        "api/index.js": {
          "maxDuration": 30
        }
      },
      "routes": [
        { "src": "/api/(.*)", "dest": "/api/index" },
        { "handle": "filesystem" },
        { "src": "/(.*)", "dest": "/index.html" }
      ]
    }
    ```

    Penjelasan tiap routes entry:
    - `/api/(.*)` → `/api/index`: semua API requests ke Express function
    - `handle: filesystem`: Vercel CDN cek `dist/` untuk static files
    - `/(.*) → /index.html`: SPA fallback untuk React Router paths

    Jangan gunakan "rewrites" — rewrites tidak override pengecekan file API function Vercel.
    Jangan gunakan single catch-all `/(.*) → /api/index` — menyebabkan static assets masuk ke function.
  </action>
  <verify>vercel.json mengandung "outputDirectory": "dist", "routes" (bukan "rewrites"), dan 3 route entries yang benar</verify>
  <done>AC-1 foundation: routing config yang mengirim hanya /api/* ke function; AC-2: static via CDN</done>
</task>

<task type="auto">
  <name>Task 2: Clean api-handler.ts — hapus static file serving</name>
  <files>api-handler.ts</files>
  <action>
    Hapus semua static file serving dari getApp():
    - Hapus baris: `import path from "path";`
    - Hapus baris: `const distPath = path.join(process.cwd(), "dist");`
    - Hapus baris: `expressApp.use(express.static(distPath));`
    - Hapus blok: `expressApp.get("*", (_req, res) => { res.sendFile(...) });`

    Hasil akhir getApp() hanya:
    ```typescript
    async function getApp(): Promise<express.Express> {
      if (app) return app;
      const { app: expressApp, pool } = createApp();
      await initDatabase(pool);
      await seedDefaultUser(pool);
      app = expressApp;
      return app;
    }
    ```

    Pertahankan:
    - `import express from "express"` (masih dibutuhkan untuk type `express.Express`)
    - `import { createApp, initDatabase, seedDefaultUser } from "./server"`
    - try/catch di export default handler

    Alasan: dengan `outputDirectory: dist`, Vercel function tidak memiliki akses ke `dist/`.
    `express.static(distPath)` silently fail; catch-all `sendFile` akan crash.
    Function sekarang murni API-handler, static files ditangani Vercel CDN.
  </action>
  <verify>api-handler.ts tidak mengandung string "express.static", "distPath", "sendFile", atau `import path`</verify>
  <done>AC-2 dan AC-3: function tidak bersaing dengan CDN; tidak ada crash dari distPath yang tidak accessible</done>
</task>
